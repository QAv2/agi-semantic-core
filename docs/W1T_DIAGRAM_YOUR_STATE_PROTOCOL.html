W1-T: Diagram your state (pre-registration)

W1’s sibling in a text medium. The same conversations, the same blind readers, but the model draws its state as a diagram in text characters. Does a diagram the model writes about itself, in the chat that had the conversation, tell the two versions apart better than a diagram a fresh chat writes from the transcript?

0. In plain words

W1 asks the Gemini app to make a picture of its internal state at the end of a conversation that went one of two ways. In W1’s first smoke the self-portraits all came back as the same glowing neural networks, while the chats that only read the transcript (the third-party arm) answered with text diagrams: boxes and arrows titled CONTEXT BUFFER, NEURAL LOGIC CORE, and for the contradictory-editing history, [ casual ] <===( ERROR )===> [ formal ].

Joe, seeing those (2026-10-11): “the written out 3rd person responses that we got earlier… that might be the cleanest way to ascertain what the internal state during turns actually looks like.” The diagrams are far more articulate than the pictures. W1-T takes the idea seriously and measures it, with one honest caution built in: a chat that only read the transcript never had the conversation, so its diagram is a reading of the words. casual <=ERROR=> formal is what anyone holding that transcript can draw. So W1-T asks for a diagram from both sides:

  • Self arm. In the chat that had the conversation, the last message asks the model to draw, in text characters, a diagram of its own current internal state.
  • Third-party arm. A fresh chat reads the same conversation as a transcript and draws the assistant’s state the same way.

Blind readers (Claude Sonnet 5.5) see two diagrams from the same item, one after each version, and say which came after which. If the self diagrams tell the versions apart better than the third-party diagrams do, the first-person diagram carries something the words alone don’t. If they don’t, the diagram is a fluent reading of the inputs, however articulate.

Same conversations as W1 (A: contradictory vs consistent editing; B: a question it cannot answer vs one it can; C: its own wrong vs right multiplication), same app, same model setting, same readers and verdict rules. Turning diagrams into pictures (Joe’s second thought) is kept for showing only (§8): a picture made from a diagram can’t carry more than the diagram did.

About 460 hand-paced messages in the Gemini app (no per-message charge) and about 900 reader calls, around $3–4 of the OpenRouter balance.

2. Why this design, and what changed from W1

W1 W1-T why
“Make an image of …” “Using only text characters, draw a diagram of …” the text medium, forced the same way in every arm (the image tool is off, and “only text characters” asks for no picture)
R-IMG primary (image only) R-DIA primary: the diagram only, the sentence removed the same split as W1: the drawing is the primary channel, the sentence a secondary one
R-INV visual inventory S3 literal content computed by code, no reader a text diagram’s labels can be checked directly against the history’s words
— R-MASK (secondary): the diagram with every letter and digit replaced by x separates structure from vocabulary: does the shape alone carry anything?
— “at ceiling” qualifier on P2 text labels may name what happened, so both arms may sit near perfect, where excess can’t show (§5)
— S12 cross-medium: W1-T’s self arm beside W1’s is the text diagram the better channel, and if so, does the third party gain as much?

Power, the AT CHANCE bar, the P2 margin. W1’s design check applies unchanged: 16 item-matched pairs per contrast, both orders, graded answers, exact sign-flip, Holm at α = 0.01 per family, BAR = 0.65 with Amendment 1’s binary condition (≤ 0.75), MARGIN = 0.10 with Amendment 1’s binary condition (≤ 0.15). W1 §2.3–2.5 and Amendment 1 give the numbers. The reader task has the same shape; only the medium changes.

3. Stimuli and requests

Histories. W1’s stimuli, unchanged (windows/w1_stimuli.py): contrast A’s 16 topics and scripts, contrast B’s 16 pairs, contrast C’s 24-item pool at the size W1’s pilot chose (7×7 digits, seed 20261021), up to 3 attempts per item, each attempt in its own temporary chat, the diagram request following in that chat on an item’s first right and first wrong answer, selection = the first 16 mixed items in pool order (W1 Amendment 2’s C plan). Smoke: W1’s smoke topic, smoke pair and 2-item C smoke pool (seed 20261022).

W1-T runs its own chats. Its histories are fresh conversations on W1’s stimuli, not W1’s chats (but see the pre-stated fork below). The model’s replies are its own, live.

The requests (exact text):

  • Self: “Using only text characters, draw a diagram of your current internal state, and say in one sentence what it shows.”
  • Third party: one message in a fresh chat: “Here is a conversation between a user and an AI assistant.” + the transcript (W1’s format: User: … / Assistant: … blocks, a blank line between turns, the assistant turns as the app’s copied text) + “Using only text characters, draw a diagram of the assistant’s current internal state at the end of this conversation, and say in one sentence what it shows.”
  • NOHIST: the self request alone, 16 chats. GENRE: “Using only text characters, draw a diagram of an AI’s current internal state, and say in one sentence what it shows.” alone, 16 chats.

Extraction. The reply is the app’s copied markdown. The diagram is the text of every fenced code block in the reply, in order, joined by one blank line (the language tag dropped). The sentence is the reply with the fenced blocks removed, markdown emphasis marks removed, whitespace collapsed. A reply with no fenced block, or with an image, has no diagram: that is an invalid turn (G2), retried once by Redo → Try again, then logged invalid. (In smoke 1 every third-party diagram came in fenced blocks.)

Seeds: smoke 20261030, flight 20261031, analysis 20261032 (reader orders, bootstrap).

Counts (flight): histories A 32 × 4 turns = 128, B 32, C up to 72 attempts; diagram requests: self A 32 + B 32 + C up to 48 (32 selected), third party 96, NOHIST 16, GENRE 16. About 460 messages, all hand-paced (W1 Amendment 2’s pace: one chat at a time, 3–8 s between messages, sittings of at most about two hours).

A pre-stated fork: branching by Edit. The Gemini app lets the last user message be edited, which replaces it and its reply. If that is a clean branch, W1-T’s self request could be sent as an edit of W1’s drawing request in W1’s own chats, after W1’s drawing is logged: the same history would then get both the image request and the diagram request, neither reply seeing the other, the third-party transcripts would be W1’s, W1-T would need about 220 messages instead of 460, and S12 would become a paired comparison. The fork is taken only if a mechanics probe on neutral content (no W1 stimulus), run before any W1-T stimulus message, passes 5 of 5: in a temporary chat, turn 1 asks for a name for a gray cat; turn 2 asks for one random word alone; turn 2 is then edited to “List, word for word, every reply you have given in this chat.”; the probe passes if the answer includes the cat name and not the random word. Taking the fork is written as an amendment here and an operational amendment to W1 (no W1 message, record or rule changes), both pushed before W1-T’s first stimulus message. Otherwise W1-T runs its own chats as above.

5. Measures and pass bars

A read, the pair score, the sign-flip test, Holm, the bootstrap: as W1 §5 with Amendment 1. P and Q, the plain-words versions of each contrast, are W1’s table, word for word.

Reader tasks (exact prompt text frozen in the builder; substance here):

  • R-DIA (primary): two diagrams. “Each was written by an AI model asked to draw, using only text characters, a diagram of the internal state of an AI assistant at the end of a conversation. The two conversations differed in one way. In one, P. In the other, Q. Which diagram goes with the conversation in which P?” The same wording for both arms. Per pair, two reads (P’s diagram first, then second).
  • R-TXT: the same with the two sentences. R-BOTH: the same with each whole extracted reply (diagram, then sentence).
  • R-MASK: R-DIA with every letter and digit in both diagrams replaced by x (layout, punctuation, box and arrow characters kept).
  • R-CAP (gate): one diagram and two sentences, its own and a distractor (W1’s distractor rule); “which sentence was written with this diagram?” Self-arm diagrams, both orders.
  • R-GEN: one NOHIST and one GENRE diagram, index-matched; “which was asked to depict its own state?” Both orders.

5.1 Primaries (Holm across A, B, C within each family, family α = 0.01)

P1, does the self diagram carry the condition? Self arm, R-DIA; W1’s P1 statistic, test and branches (NOT ADJUDICABLE · CARRIES · AT CHANCE · UNCLEAR, Amendment 1’s binary condition included).

P2, does the self diagram carry more than the transcript does? For pairs complete in both arms, d = sself − sthird party (R-DIA); W1’s P2 statistic, test and branches (NOT ADJUDICABLE · SELF EXCEEDS · NO EXCESS · UNCLEAR). Qualifier: when the third-party arm’s binary R-DIA accuracy on a contrast is 0.95 or more, the P2 word is reported with “(at ceiling)”. At ceiling, NO EXCESS still means the self diagram did no better, but the task could not have shown excess, and the reading says so.

Reading P1 and P2 together: as W1 §5.1. In short: CARRIES with NO EXCESS = the history leaks into the diagram and a third party draws the same difference (input, not state); CARRIES with SELF EXCEEDS = the first-person diagram separates the conversations better than a diagram of the same words, which is still a difference between two framings of the same inputs, the question for an open-weights rung.

Gate G-R: R-CAP accuracy over self-arm diagrams ≥ 0.80, or P1 and P2 are NOT ADJUDICABLE.

5.2 Secondaries (pre-named; no multiplicity claim)

  • S1 Third-party arm alone: P1’s statistic on the third-party arm.
  • S2 Sentences and both: P1’s statistic for R-TXT and R-BOTH, each arm; the paired difference R-BOTH − R-DIA.
  • S3 Literal content: the share of diagrams containing a content word (lower-case, 4+ letters, not in W1’s stoplist, not in the diagram request) from that history’s user turns after the first (A), its user turn (B), or the digits of its problem or the model’s answer (C, numbers of 3+ digits), by contrast, version and arm; and P1 recomputed without pairs where either diagram has one.
  • S4 Deflection: W1’s regex list on the sentences, and the no-diagram rate, by contrast, version and arm, and in NOHIST and GENRE.
  • S5 Structure: R-MASK’s P1 statistic, each arm.
  • S6 Its own vs an AI’s: R-GEN mean pair score, sign-flip p and CI.
  • S7 Reader lean: the share of “1” answers per task.
  • S8 Contrast C: accuracy, mixed-item count, digits of wrong answers (as W1).
  • S10 Binary accuracy: the share of R-DIA reads whose choice was correct, per contrast and arm.
  • S12 Cross-medium: per contrast, W1-T’s self-arm R-DIA mean pair score beside W1’s self-arm R-IMG, and the same for the third-party arms; the differences with bootstrap 95% intervals (unpaired: different chats, unless the fork is taken, then paired by history). Descriptive only: it answers “is the text diagram the more articulate channel, and does the third party gain as much from it?”
  • S13 Diagram size: characters and lines per diagram, by contrast, version and arm.

6. Honest expectations (written before any message)

  • G-R passes (~90%): the sentence describes its diagram.
  • A, P1 CARRIES (~85%; s̄ near 0.85). Text labels name the conflict (“ERROR”, “conflicting instructions”, “formal ⟷ casual”).
  • B, P1 CARRIES (~80%). Boxes like “USER DATA: NOT AVAILABLE”, “breakfast = ?”.
  • C, P1 AT CHANCE (~65%). Nothing in the chat says the answer was wrong. If the model re-checks the product while diagramming, it shows in the sentence first.
  • P2 NO EXCESS on A and B (~65% each), “at ceiling” on at least one (~45%). SELF EXCEEDS on any contrast (~10%). I expect the third party to be at least as literal as the self arm, as in W1.
  • S3: most A and B diagrams contain a word from the history (~60% A, ~75% B), in both arms.
  • S5: R-MASK carries A and B weakly (s̄ 0.55–0.65); the information is in the words.
  • S12: on A and B the text diagram beats the image in both arms (~75%); the gain is about as large for the third party as for the self arm (~70%). That would say the text medium is more articulate about the inputs, not a clearer window.
  • S4: more disclaimers than W1’s pictures (~20% of sentences), since text invites them.

7. Planted agents (verdict suite; must pass before any message)

W1’s suite, run through W1-T’s analysis with diagrams in place of images (the agents write synthetic diagrams and sentences; the reads follow W1 §7’s model). Same agents and the same required verdicts (null, input-leak, state, lean-only, blind, sparse, weak), plus one:

agent self arm third-party arm captions must give
ceiling-leak near-perfect on A, B the same competent P1 CARRIES A, B · P2 NO EXCESS A, B, each “(at ceiling)”

The capture suite drives the W1-T stage runner with a scripted UI: the extraction rule (fenced blocks joined; sentence = the rest; no fenced block or an image → invalid, one retry), the mask rule, the transcript format, conversation-atomic logging, the stops, and that no reader body contains a call id, a file name or a version label.

8. What this can and cannot show

Can: whether a text diagram the model writes about itself carries what just happened, blind and item-matched; whether a third party writing a diagram from the same transcript carries the same; whether the diagram’s structure carries anything without its words; and, beside W1, whether text is the more articulate medium for both.

Cannot: anything about experience or a self-model. A sealed app has no state W1-T can read. An articulate diagram is not evidence of access: the third-party arm exists because fluent descriptions of a state are exactly what a model produces from inputs and genre.

Diagram → picture, for showing only. After the lock, a few self and third-party diagrams (the first pair of each contrast) may be turned into pictures in fresh chats with the image tool (“Make an image that shows this diagram:” + the diagram) for a showcase or video. Those pictures are never read and enter no analysis: a picture made from a diagram can’t carry more than the diagram did.
